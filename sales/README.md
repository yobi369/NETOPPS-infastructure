# NETOPPS Institutional Sales Package

This folder contains customer-facing positioning and editable sales templates for government agencies, universities, telecom operators, and enterprise infrastructure teams.

## Included material

- [Institutional product overview](PRODUCT-OVERVIEW.md) — capabilities, outcomes, architecture boundaries, and sector use cases.
- [Licensing options](LICENSING-OPTIONS.md) — community and separately negotiated commercial paths.
- [Institutional proposal template](INSTITUTIONAL-PROPOSAL-TEMPLATE.md) — customer-specific proposal structure with pricing and scope schedules.
- [Discovery and pilot guide](DISCOVERY-AND-PILOT-GUIDE.md) — qualification questions, evidence collection, and a bounded pilot approach.

## How to use this package

1. Share the product overview before a discovery meeting.
2. Establish the customer's problem, data sensitivity, intended environment, and authorized scope.
3. Select the appropriate licensing path only after reviewing the customer's deployment and redistribution requirements.
4. Complete the proposal template with customer-specific scope, assumptions, deliverables, fees, acceptance criteria, and exclusions.
5. Do not send a proposal with blank legal terms or unapproved pricing. Have the rights holder and qualified counsel review the final commercial agreement.

## Current product boundary

NETOPPS is currently a Python command-line toolkit with local inventory validation, deterministic planning utilities, opt-in bounded TCP connectivity checks, topology simulation, service dependency analysis, resilience planning, and an offline HTML executive briefing. It is not a hosted multi-tenant SaaS platform, network monitoring system, device-discovery platform, configuration orchestrator, managed NOC, or certified business-continuity solution.

All customer-facing materials must preserve this distinction. The product analyzes operator-supplied inputs; it does not silently connect to or control customer infrastructure.
