NETOPPS / INSTITUTIONAL PILOT
Controlled evaluation workflow

From authorised scope to evidence-backed resilience decisions.

The NETOPPS Institutional Pilot Edition provides a structured way for an institution and its technical reviewers to define scope, validate input evidence, run a baseline assessment, compare a proposed design and agree an executive outcome.

Important data boundary: This is a public information page, not a secure customer portal. Do not enter or upload confidential topology, credentials, personal data or production network information here. The pilot workflow is executed locally using the NETOPPS Python CLI in an institution-approved environment.
01 / AUTHORISE

Controlled onboarding

Agree sponsor, technical and data owners, written authorization, permitted environment, scope and stop conditions.

02 / INVENTORY

Structure the model

Prepare versioned assets, sites, links, services and dependency relationships with stable identifiers.

03 / EVIDENCE

Validate provenance

Record source, owner, date, freshness, reviewer, permitted use and known limitations for each input.

04 / BASELINE

Assess current design

Run the existing local resilience engine and review modeled impacts, capacity gaps and recovery priorities.

05 / IMPROVE

Compare a candidate

Create a separate candidate dependency model and compare it against the same baseline scope and assumptions.

06 / DECIDE

Executive assessment

Present evidence-backed findings, modeled differences, unresolved risks, accepted actions and a documented pilot outcome.

Method and limitations

Evidence first. No unsupported claims.

NETOPPS models operator-supplied topology, service dependencies, declared capacity, failure domains and recovery objectives. Its reports are deterministic planning outputs, not outage probabilities, certified physical diversity, live telemetry, verified failover performance or guarantees of restoration.

A candidate improvement is a hypothesis until the institution validates its technical independence, capacity, support coverage and operational behavior. Production testing or changes require separate written authorization and change control.
