# Using the NETOPPS Engine Report Viewer

The public [Engine Report Viewer](https://netopps.vercel.app/analysis/) renders a JSON report generated by the actual local Python resilience engine. It does not run analysis in the browser and does not upload the selected report.

## Generate a report

From a local NETOPPS checkout, run:

```bash
netopps resilience-report examples/telecom-evaluation-topology.json examples/telecom-evaluation-services.json --format json --output telecom-resilience-report.json
```

To compare a concrete candidate dependency model:

```bash
netopps resilience-report examples/telecom-evaluation-topology.json examples/telecom-evaluation-services.json --candidate-dependencies examples/telecom-evaluation-services-candidate.json --format json --output telecom-resilience-comparison.json
```

Open the viewer and select the generated JSON file. The file is read locally in the browser tab; it is not sent to NETOPPS or Vercel. The viewer accepts the version-1 `institutional-resilience-and-recovery-plan` report contract and displays executive metrics, service state, weakest dependencies, redundancy recommendations, capacity assessment, correlated failure domains, recovery priorities, candidate comparison metrics when present, and engine limitations.

## Trust and safety boundaries

- The analysis is performed by the local Python CLI, not by the viewer.
- The viewer validates the report type and model version before rendering.
- The viewer uses text-only DOM insertion for report content and does not interpret model-supplied strings as HTML.
- File selection is local to the browser; no report upload endpoint exists.
- The viewer enforces a 5 MiB input limit. The CLI has its own bounded input parsing.
- Use synthetic or sanitised data for public demonstrations. Do not place credentials, secrets, subscriber data, or sensitive production topology in public repositories or screenshots.
- All findings remain conditional on supplied topology, dependencies, capacity, criticality, failure-domain and recovery inputs. This is not live telemetry, a carrier integration, an outage forecast, or a failover guarantee.

The guided browser demo at `/demo/` remains an illustrative interactive model. The engine report viewer is a separate way to inspect actual CLI-generated JSON output.
