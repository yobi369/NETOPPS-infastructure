# Institutional Pilot Acceptance Checklist

Complete jointly with the institution. A generated report alone is not acceptance.

## Gate 1 — Authorization and scope

- [ ] Written authorization and named institutional sponsor recorded.
- [ ] Technical, data, security and review owners assigned.
- [ ] Scope, exclusions, permitted environment and assessment window approved.
- [ ] Data classification, retention, deletion and permitted use agreed.
- [ ] Stop / re-scope conditions accepted.

## Gate 2 — Inventory and evidence

- [ ] Stable identifiers used for assets, sites, links and services.
- [ ] Topology, service and dependency input versions recorded.
- [ ] Evidence register populated with source, owner, timestamp and reviewer.
- [ ] Capacity values include units, source and measurement window.
- [ ] Failure-domain labels and physical-diversity claims have supporting references.
- [ ] Unknown, stale, conflicting and unverified inputs remain explicitly flagged.
- [ ] No secrets, personal data or unauthorized production details included.

## Gate 3 — Baseline analysis

- [ ] Baseline files frozen and cryptographic hashes recorded by the institution.
- [ ] Schema and semantic validation completed.
- [ ] Baseline resilience report generated using the approved NETOPPS version.
- [ ] Critical findings reviewed by institutional engineers.
- [ ] Accepted, rejected, duplicate and unresolved findings dispositioned.
- [ ] Model limitations and data gaps documented.

## Gate 4 — Candidate improvement

- [ ] Candidate input is a separate version; baseline is unchanged.
- [ ] Each proposed alternative has a named owner and evidence reference.
- [ ] Independence, reachability, failover support and capacity are validated or clearly marked as assumptions.
- [ ] Candidate comparison uses the same agreed scope and scenario set.
- [ ] No modelled improvement is presented as a guaranteed real-world outcome.

## Gate 5 — Executive assessment

- [ ] Baseline and candidate input versions are stated.
- [ ] Service-state, capacity-gap and recovery-priority differences are explained.
- [ ] Evidence-backed findings are separated from assumptions.
- [ ] Analyst effort and other value measures use agreed denominators and source records.
- [ ] Unresolved risks, exclusions and confidence limitations are visible.
- [ ] Recommendations have owners, next steps and approval status.

## Gate 6 — Closeout

- [ ] Institution has reviewed and dispositioned findings.
- [ ] Deliverables and acceptance thresholds checked against the charter.
- [ ] Data retention and deletion actions completed or assigned.
- [ ] Pilot outcome recorded: accepted / accepted with conditions / re-scope / not accepted.
- [ ] Any next phase requires separate authorization and commercial agreement where applicable.
